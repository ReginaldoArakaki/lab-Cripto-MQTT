Criptografia Simétrica: Cifra de César e Modos do AES

Na criptografia simétrica, remetente e destinatário compartilham exatamente a mesma chave secreta (K) para cifrar e decifrar mensagens. Ela é computacionalmente rápida e ideal para grandes volumes de dados (como payloads IoT e streams), mas exige cuidado extremo com o modo de operação da cifra de bloco.

Laboratório Interativo 1B · Cifra de Bloco AES-128/256

Por que AES-ECB Vaza Informação Visual e CBC/CTR Não

O algoritmo AES processa blocos fixos de 128 bits (16 bytes). No modo ECB (Electronic Codebook), blocos de entrada idênticos geram exatamente os mesmos blocos cifrados — preservando contornos e padrões visuais inteiros da imagem ou estrutura original. Os modos CBC (encadeado com IV) e CTR (fluxo via Nonce + Contador) eliminam essa correlação por completo.

Entrada · Texto Claro Original (Sem Cifra) 64 blocos de 4×4 px
Inseguro · Determinístico AES-ECB (Vaza Padrões) Blocos repetidos visíveis!
Seguro · Encadeado (IV) AES-CBC (P_i XOR C_{i-1}) Entropia uniforme · 0 colisões
Seguro · Paralelo (Nonce) AES-CTR (Keystream) Sem padding · 0 colisões

Modo AES Mecanismo Exige IV / Nonce? Exige Padding? Segurança contra Padrões
ECB Cada bloco é cifrado isoladamente: C_i = E_K(P_i) Não Sim (PKCS7) Inseguro (Vaza padrões)
CBC XOR com bloco cifrado anterior: C_i = E_K(P_i ^ C_{i-1}) Sim (IV aleatório 16 B) Sim (PKCS7) Seguro (Cifra semântica)
CTR Cifra contador e aplica XOR: C_i = P_i ^ E_K(Nonce||i) Sim (Nonce único 16 B) Não (Cifra de fluxo) Seguro e Paralelizável
Python · 01_cifra_cesar.py 
def cifra_cesar(texto: str, deslocamento: int) -> str:
    resultado = []
    for ch in texto:
        if 'A' <= ch <= 'Z':
            base = ord('A')
            resultado.append(chr((ord(ch) - base + deslocamento) % 26 + base))
        elif 'a' <= ch <= 'z':
            base = ord('a')
            resultado.append(chr((ord(ch) - base + deslocamento) % 26 + base))
        else:
            resultado.append(ch)
    return "".join(resultado)

msg = "MQTT_SENSOR_OK"
cifrado = cifra_cesar(msg, 3)
print("Cifrado:", cifrado)
print("Decifrado:", cifra_cesar(cifrado, -3))
Python · 02_aes_ecb_cbc_ctr.py (cryptography) 
import os
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
from cryptography.hazmat.primitives import padding

chave = os.urandom(32)  # AES-256 (32 bytes)
# Dois blocos identicos de 16 bytes para testar ECB vs CBC/CTR
dados = b"BLOCO_SECRETO_01" * 2

# 1) AES-ECB (INSEGURO: blocos repetidos ficam identicos!)
ecb = Cipher(algorithms.AES(chave), modes.ECB()).encryptor()
ct_ecb = ecb.update(dados) + ecb.finalize()
print("ECB bloco 1 == bloco 2?", ct_ecb[:16] == ct_ecb[16:])  # True!

# 2) AES-CBC (SEGURO: requer IV aleatorio + padding PKCS7)
iv = os.urandom(16)
padder = padding.PKCS7(128).padder()
dados_pad = padder.update(dados) + padder.finalize()
cbc = Cipher(algorithms.AES(chave), modes.CBC(iv)).encryptor()
ct_cbc = cbc.update(dados_pad) + cbc.finalize()
print("CBC bloco 1 == bloco 2?", ct_cbc[:16] == ct_cbc[16:])  # False!

# 3) AES-CTR (SEGURO: cifra de fluxo via Nonce, sem padding)
nonce = os.urandom(16)
ctr = Cipher(algorithms.AES(chave), modes.CTR(nonce)).encryptor()
ct_ctr = ctr.update(dados) + ctr.finalize()
print("CTR tamanho exato:", len(ct_ctr), "bytes")
Módulo 02 · Autoestudo 4 · Chaves Pública/Privada & Certificação

Criptografia Assimétrica: RSA e Assinaturas Digitais

A criptografia assimétrica resolve o problema da distribuição de chaves ao utilizar um par matematicamente vinculado: uma Chave Pública (que pode ser divulgada livremente) e uma Chave Privada (sigilo absoluto do proprietário). A direção de uso define a propriedade de segurança obtida.

Fluxo 1 — Confidencialidade (Cifrar Mensagem) Remetente cifra usando a Chave Pública do Destinatário. Somente o destinatário consegue decifrar usando sua própria Chave Privada.
Fluxo 2 — Autenticidade e Integridade (Assinar Digitalmente) Remetente assina o hash da mensagem usando sua própria Chave Privada. Qualquer pessoa verifica a assinatura com a Chave Pública do Remetente.

Python · 03_rsa_chaves_e_assinatura.py (cryptography) 
from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.primitives import hashes

# 1. Geracao do par de chaves RSA (2048 bits)
chave_privada = rsa.generate_private_key(public_exponent=65537, key_size=2048)
chave_publica = chave_privada.public_key()

# 2. CONFIDENCIALIDADE: Cifrar com Chave Publica e Decifrar com Privada
mensagem = b"Credencial MQTT: user=sensor01;pass=T17_Segura"
cifrado = chave_publica.encrypt(
    mensagem,
    padding.OAEP(
        mgf=padding.MGF1(algorithm=hashes.SHA256()),
        algorithm=hashes.SHA256(),
        label=None,
    ),
)
decifrado = chave_privada.decrypt(
    cifrado,
    padding.OAEP(
        mgf=padding.MGF1(algorithm=hashes.SHA256()),
        algorithm=hashes.SHA256(),
        label=None,
    ),
)
print("Decifrado:", decifrado.decode())

# 3. INTEGRIDADE & AUTENTICIDADE: Assinar com Privada e Verificar com Publica
assinatura = chave_privada.sign(
    mensagem,
    padding.PSS(mgf=padding.MGF1(hashes.SHA256()), salt_length=padding.PSS.MAX_LENGTH),
    hashes.SHA256(),
)
# Se 1 unico byte da mensagem for alterado, verify() lanca InvalidSignature
chave_publica.verify(
    assinatura,
    mensagem,
    padding.PSS(mgf=padding.MGF1(hashes.SHA256()), salt_length=padding.PSS.MAX_LENGTH),
    hashes.SHA256(),
)
print("Assinatura digital verificada com sucesso!")
Módulo 03 · Integridade & Efeito Avalanche

Funções Hash Criptográficas: MD5, SHA-256 e HMAC

Uma função hash mapeia dados de tamanho arbitrário em uma impressão digital (digest) de tamanho fixo. Diferente da criptografia, o hash é unidirecional (não há decifragem). Enquanto o MD5 (128 bits) é considerado quebrado por vulnerabilidades de colisão, o SHA-256 (256 bits) é o padrão de mercado para verificação de integridade.

Laboratório Interativo 3 · Hash Real em Navegador

Comparador MD5 vs SHA-256 e Medidor de Efeito Avalanche

Altere um único caractere entre a Entrada A e a Entrada B para observar o efeito avalanche: uma mudança mínima na entrada altera aproximadamente 50% de todos os bits da saída SHA-256.

MD5 (128 bits · 32 hex · Obsoleto)
SHA-256 (256 bits · 64 hex · Seguro)
MD5 (128 bits · 32 hex · Obsoleto)
SHA-256 (Destaque nos nibbles alterados)
Divergência de Bits no SHA-256 (Efeito Avalanche)

Atenção em redes MQTT: enviar apenas payload + SHA256(payload) não impede adulteração por um atacante em trânsito, pois o atacante pode alterar o payload e recalcular o SHA-256! Para garantir integridade autenticada, use HMAC-SHA256 (hash com chave secreta) ou assinatura RSA.

Python · 04_hashes_hashlib_e_hmac.py 
import hashlib
import hmac

payload = b'{"sensor": "temp_sala", "valor": 25.0}'

# 1. MD5 (nao recomendado para seguranca; sujeito a colisoes)
digest_md5 = hashlib.md5(payload).hexdigest()

# 2. SHA-256 (padrao atual para verificacao de integridade)
digest_sha256 = hashlib.sha256(payload).hexdigest()
print("MD5    :", digest_md5)
print("SHA-256:", digest_sha256)

# 3. HMAC-SHA256: Integridade + Autenticacao com chave compartilhada
chave_secreta = b"segredo_compartilhado_iot"
tag_hmac = hmac.new(chave_secreta, payload, hashlib.sha256).hexdigest()

# Validacao segura contra ataques de tempo (timing attack)
tag_recebida = hmac.new(chave_secreta, payload, hashlib.sha256).hexdigest()
integro = hmac.compare_digest(tag_hmac, tag_recebida)
print("HMAC valido?", integro)

Segurança e Ataques em MQTT pela Tríade CIA

O MQTT (Message Queuing Telemetry Transport) opera no modelo Publish/Subscribe mediado por um Broker. Por padrão, brokers públicos de teste na porta 1883 (TCP) trafegam mensagens em texto claro, sem autenticação ou ACLs — expondo os três pilares da segurança: Confidencialidade, Integridade e Disponibilidade.

Pergunta do Autoestudo 6: O que ocorre se deixarmos o mesmo Client ID? De acordo com a especificação MQTT (v3.1.1 / v5.0), o Client Identifier (Client ID) deve ser único por cliente conectado ao Broker. Se um segundo cliente conectar usando o mesmo Client ID de uma sessão ativa, o Broker aceita a nova conexão e desconecta imediatamente o cliente anterior (mecanismo de Session Takeover). Quando explorado repetidamente por um atacante em loop, causa o ataque de Desapropriação de Client ID (Hijacking), impactando diretamente a Disponibilidade.
